# 2026.272.2039 — fix(plugin-check): adopt the sdk ctx requirement on the deploy-config family

## Summary

`sdk#288` (`v0.2026271.915`) added a **`context.Context` parameter** to the `deploykit`
deploy-config family, removing the fail-open default so each invocation resolves its OWN
per-box overlay via `kit.DefaultDeployConfigPath(ctx)`. Without a bumped `sdk`, this plugin's
compiled-in candy cannot build against the `#717` fix version (`sdk v0.2026272.1813`), which
blocks `opencharly/charly#733` → `#714`. This PR adopts `ctx` in `plugin-check` and bumps
`sdk`/`spec` to the ctx-ready tags.

### Threaded the REAL ctx (no fabrication)

Every enclosing function already carries the genuine ctx threaded from the plugin's
`Invoke(ctx, req)` dispatch (the live/feature gather arms take `ctx context.Context` as a
parameter — `pluginCheckLivePod`, `pluginCheckLiveVM`, `pluginCheckRunFeatureLivePod`,
`pluginCheckRunFeatureLiveVM`, `instrumentRunnerFor`, `resolveHostVars`, `resolveCheckVenue`).
Only `resolveContainerDeclared` lacked a ctx in scope, so it gains one (threaded from its sole
caller, `pluginCheckLivePod`) purely to reach `ResolveBoxEngineForDeploy`. `context.Background()`
is **not** used in any production path — the ctx selects the invocation's overlay.
