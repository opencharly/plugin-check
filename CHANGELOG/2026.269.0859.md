# 2026.269.0859 — feat(kubevirt): the plugin-check kubevirt bed arm + venue resolution

feat(kubevirt): the plugin-check kubevirt bed arm + venue resolution

Rounds out the KubeVirt substrate: a check bed whose **ROOT** is a `kubevirt:` deploy —
a cluster-managed `VirtualMachine` CR whose lifecycle `candy/plugin-kubevirt` owns — now
brings up, probes, and tears down through the correct arm instead of falling through to
the pod path (or, before the venue split, the `charly vm` libvirt path).

> **Landing order:** carries the spec/sdk pin bumps for the landed venue split
> (spec#166/#168 → sdk#294). No new spec surface — the classifier calls the
> already-landed `deploy.SshVenue` / `deploy.IsVmVenue`.

## Summary of changes

- **`candy/plugin-check/bed_run.go`** — `isKubeVirt` (computed from the bed-root's stamped
  `Descent`, the descriptor the host already carries in `NodeJSON` — no new wire field)
  selects a new **bring-up arm**: a single `charly deploy add <bed>` (the plugin lifecycle:
  ensure DataVolume, apply VM CR, wait VMI Ready + AgentConnected, open the managed
  `virtctl port-forward`, publish the ssh stanza), then readiness on the managed ssh alias.
  The image build / feature-run steps are skipped (no pod image); teardown is
  `charly deploy del` (the plugin's `OpPostTeardown` removes the CR + stops the
  port-forward). Pre-run cleanup + the fresh-rebuild gate mirror it.
- **`candy/plugin-check/venue.go`** — the classifier now calls the landed
  `deploy.SshVenue` / `deploy.IsVmVenue`; `checkVmTarget` matches **any ssh-transport
  venue** (the host-libvirt vm AND kubevirt), so the guest ssh executor is built for both
  behind the identical `kit.VmSshAlias(VmDomainIdentity(name))` alias. `checkLocalTarget`
  is unchanged.
- **`candy/plugin-check/live_gather_kubevirt.go`** — a kubevirt live-gather over the
  managed ssh alias: the plan comes off the kubevirt deploy node (no libvirt domain, no
  `port_forwards` allocation table, no `VirtualMachineSnapshot`).
- **`candy/plugin-check/feature_run_gather.go`** — the ADE feature-live dispatch routes a
  kubevirt root to the ssh (VM) arm.
- **`candy/plugin-check/venue_test.go`** — the fixtures are now built through the REAL
  trait derivation (`spec.DescentFromTraits`, the same table the provider declares), so a
  predicate reading `Transport`/`Venue`/`ExclusiveVenue` is exercised against live-shape
  data, not a hand-built stub.
- **`candy/plugin-check/venue_kubevirt_test.go`** — new: pins the classifier (a kubevirt
  node is ssh-transport WITHOUT `ExclusiveVenue`; the vm and pod are excluded).
- **`candy/plugin-check/live_gather.go`** — the check-live dispatch hook: a kubevirt root
  routes to the dedicated gather before the vm arm.
- **`candy/plugin-check/live_gather_test.go`** — the feature-dispatch fixture now builds
  its Descent through the real trait derivation (the shared `desc()` helper).
