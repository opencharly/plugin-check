# 2026.270.0151 — fix(bed-run): build a bed's image for external-in-place deploys too (kindcluster workload)

## Summary

`charly check run` skipped the image-build step for an **external-in-place** deploy
(`!d.IsExternal` in the Steps 1+2 guard, `bed_run.go`). That guard was written when the
only external-in-place substrate was `kind:local` (which carries no image) — but the
`kindcluster` substrate's deploy provisions a cluster **and applies an optional WORKLOAD
IMAGE**, whose ref its preresolve pins as `<image>:<deploy>-<calver>` and loads into the
kind node (`kind load image-archive`). With the build skipped, the kindcluster preresolve
failed:

```
charly: error: … preresolve substrate "kindcluster": … deploy "check-kindcluster-workload":
pinned image "check-k8s-deploy-app:check-kindcluster-workload-2026.270.0101"
not present in local podman storage
```

**Fix:** extract the predicate to `bedBuildsImage(isVM, isKubeVirt, isLocal, image)` and
key it on a non-empty `Image` instead of excluding external-in-place — a `kind:local`
deploy (no image) stays skipped, a kindcluster workload is built. A VM/kubevirt substrate
stays skipped (an image-backed CR).

`ctr images import` saw an empty archive — and is fixed in its own PR,
`opencharly/plugin-kube#10`, which the run above carries as a repo override.)
