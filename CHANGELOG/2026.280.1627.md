# 2026.280.1627 — fix(check): dispatch a resolved non-host leaf on ITS venue, not the host root (#86)

## Summary

`checkLocalTarget` resolved a dotted name's **LEAF** and then, when that leaf was **not** host-venue, fell through to the **ROOT** fallback:

```go
if leaf, venue, ok := resolveLeafVenue(tree, name); ok {
	if venue == "shell" || venue == "parent" || venue == "none" {
		return leaf, true
	}
}
// (root fallback follows)
```

So a dotted name whose leaf is a **pod under a host-venue (`kind: local`) root** was mis-routed into the LOCAL arm — dispatching on a name whose leaf it had already resolved as **not** local. The resolved leaf now decides the dispatch:

```go
if leaf, venue, ok := resolveLeafVenue(tree, name); ok {
	return leaf, venue == "shell" || venue == "parent" || venue == "none"
}
```

This was split out of opencharly/plugin-check#85 (see #86) precisely because the local-bed R10 that witnesses #78 cannot distinguish it — its target's leaf is host-venue, so both forms return identically. It now carries its own witness.

**The witness shape is authorable** — established before writing the change, not assumed: a `kind: local` body may carry an in-substrate resource member, and the member-bearing root decodes as a deploy node (so it is *not* usable as a `from:` template — the fixture therefore splits the template from the root).
