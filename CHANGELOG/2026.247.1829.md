# 2026.247.1829 — feat(check): a clone bed auto-provisions its missing base golden (fresh lane + retry)

## Summary

Implement the missing **auto-provisioning** functionality (measured gap, R1): a clone-based check bed whose BASE golden does not exist now auto-provisions the base bed's FRESH lane (captures the golden), STOPS the base's keep_venue domain (so the golden is not locked), and retries the vm-build once.

- **bed_autoprovision.go**: the missing-golden signature regex + the runner-error LOG-SCAN (the step error is the subcommand SUMMARY; the detail lives in the referenced vm-build.log), the real disposable guard predicate `baseIsProvablyBed` (beds follow the project `check-*` convention; `charly check run` itself refuses non-disposable beds as the enforceable backstop), `autoProvisionBaseGolden` (parse + guard, returns the parsed BASE), and **`buildVmWithProvisionRetry` — the production seam** (parses, provisions the parsed base, retries once).
- **bed_run.go**: the vm-build fail path calls `buildVmWithProvisionRetry` with the real step + provisionBaseGoldenRun.

### Fail-fast polling (final head)
The auto-provision no longer uses a flat wall-clock timeout: it polls the base run's phase-log progress (5s tick) and FAILS FAST when no phase advances for 2 minutes — the stalled-run class (measured: a run stuck post-vm-create for 23 min) now fails in ~2 min.
