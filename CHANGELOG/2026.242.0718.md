# 2026.242.0718 — fix: collect baked check: steps from a remotely-pinned add_candy

## Summary

`candyAddSteps` skipped every `@github` ref outright:

```go
if deploykit.IsRemoteCandyRef(ref) {
    continue
}
```

so a bed whose `add_candy:` pins a candy by ref — the normal form since the de-submodule
cutover — contributed **none** of that candy's baked `check:` steps. The bed then ran only
its own plan steps and **passed**, asserting almost nothing. That is worse than failing: a
green bed that checks nothing draws no attention.

The skip was unnecessary. `BareRef` is the map-key form (no `@`, no `:version`) and
`rp.CandyModels` keys a **fetched** candy by exactly that — the sibling
`candyDirsFromEnvelope` says so in its own doc comment. Local and remote are the same
lookup.

Closes opencharly/charly#469.

## How tested

**The measurement that found it** — a controlled A/B on a disposable Arch cloud-image VM
bed. Same VM entity, same candy *content*, same bed shape; only the reference style differs.
Each bed carries one marker step of its own so neither arm can be zero-step:

| arm | `add_candy:` | `check-live` steps | of which the candy's baked checks |
|---|---|---|---|
| local | `punktfunk-local` (discovered) | **14** (12 passed, 2 skipped) | **11** |
| remote | `@github.com/opencharly/layer-punktfunk:v2026.241.2145` | **1** | **0** |

The remote arm's entire `check-live`:

```
  PASS  check bed-own marker so the arm is never zero-step  [ab-remote-marker]  exit=0
```

Both arms deployed successfully and both reported `PASS (steps=9)` overall, so nothing
surfaced the difference.

**The committed regression test fails without the fix**, with the same symptom:

```
--- FAIL: TestCandyAddStepsIncludesRemoteRefs
    remote @github ref ("@github.com/opencharly/layer-probe:v2026.242.1200"):
      no steps collected — the candy's baked checks were dropped
FAIL
```

and passes with it, for the remote and local ref in the same table-driven case:

```
--- PASS: TestCandyAddStepsIncludesRemoteRefs (0.00s)
--- PASS: TestCandyAddStepsUnknownRefIsSkipped (0.00s)
```

Verified by restoring only the `IsRemoteCandyRef` skip with the test in place, then removing
it again — so the test is demonstrably coupled to the change.

`TestCandyAddStepsUnknownRefIsSkipped` pins the other half: a ref with no scanned candy still
contributes nothing rather than panicking or inventing steps.

**No regressions:**

```
$ GOWORK=off go test ./...     EXIT=0   (1 package ok, 0 failures)
$ GOWORK=off go vet ./...      (clean)
$ gofmt -l .                   (clean)
```

The test fixture deliberately carries only a `check:` step: a `run:` step routes
`BakeableSteps` through `spec.OpInContext`, which needs the verb catalog the real binary
initialises, and the bakeable-vs-not split is not what this test is about.
