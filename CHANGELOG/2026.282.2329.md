# 2026.282.2329 — fix(check): one declared vocabulary for every check-run gather, with a cwd fallback (a dead assertion now FAILS on the box path)

## Summary

`opencharly/plugin-check#95`. `newPluginCheckRunner` takes a **required** vocabulary, so the compiler forced all twelve call sites to answer — and **six answered `nil`**, which means `UnresolvedConditional` for everything. On the box-check and instrument paths a dead assertion therefore stayed a skip, and a plan that had stopped asserting read exactly like a plan that passed.

### The question the issue left open, answered by measurement

It said: *"Not claimed here: which of the five gathers already has an envelope in reach without a fetch."*

**Exactly one — and in the caller, not the function.** `score_live.go` does *not* resolve the project where the runner is built; `pluginRunCheckLive` resolves it once and passes only `derefDeployTree(rp.Deploy)` down:

```go
// score_live.go:75, in the CALLER
if rp, rerr := resolvedProject(ex, ctx, dir); rerr == nil && rp != nil {
    deployRoots = derefDeployTree(rp.Deploy)
}
// :84 — the roots travel, the envelope does not
pluginScoreOneVenueBucket(ex, ctx, dir, bucket, deployRoots, out, verdictByID)
```

So the scored leg needs **no second fetch at all**. The other four each carried a source they were not using: `req.Dir` (`spec.CheckRunRequest.Dir` exists), `in.Dir`, and the plugin's own cwd.

`declaredVocabularyFor(ex, ctx, dir)` is now the **one** place a gather obtains it — best-effort, `nil` where a project genuinely cannot be resolved, **never a failure invented from a lookup error**.

### The fallback is not a convenience; it is the change

`charly check box` dispatches `Mode:"box"` with an `Image` and **nothing else** — no `Dir`. So the first version, which asked for `req.Dir`, received `""` and correctly returned nil: **it was inert on precisely the path it was written for**, while its unit test passed.

`vocabularyDir(dir)` now falls back to the process working directory when the request carries none — the box check runs in the project that dispatched it — and the fallback is asserted directly (`vocabularyDir("") == projectDirFromCwd()`) rather than assumed.

## A note on how long this took, because it is the useful part

**The bed caught two things reading would not have.** The first was the `req.Dir` inertness above. The second was my own conclusion: after fixing it I re-ran the box check, saw it still skip, and reasoned from file timestamps that the rebuilt binary therefore *contained* the fix — writing a "genuine negative" onto the issue.

**It was a stale binary.** `scripts/bootstrap-charly.sh` builds through a `go.work.dev` workspace, so a `replace` in `charly/go.mod` never reached that build: the run had used the *released* plugin-check. The decisive probe was a format string that cannot be inlined away — `strings bin/charly | grep -c 'PROBE declaredVocabularyFor'` returned **0**, which no amount of inference from mtimes could have told me. Built through the harness that carries the replaces, the same probe returned `1` and the same box check returned **`FAIL`**.

**A timestamp proves a binary was built; it does not prove what is in it.** The correction is on the issue, and the run above was repeated after that correction with the probe removed, so the pasted AFTER is the final artefact rather than a debug build.
