# 2026.241.2225 — fix: the pacman --needed allowance missed every epoch-versioned package

## Summary

The `pacman-needed-package-already-current` diagnostic allowance claims pacman's `--needed`
acknowledgement — `warning: <pkg> is up to date -- skipping` — so a candy declaring a package the
base image already ships does not report a warning nothing can fix.

Its character class had no `:`. pacman renders an **epoch** as `<name>-<epoch>:<ver>-<rel>`
(`rust-1:1.98.0-1.1`, `ffmpeg-2:9.0.1-1`), so the colon ended the match and **every
epoch-versioned package fell straight through the allowance** — producing an un-allowlisted
warning whose text is character-for-character the sentence the entry exists to exempt.

```diff
-		Match:    regexp.MustCompile(`^warning: [A-Za-z0-9_.+-]+ is up to date -- skipping$`),
+		Match:    regexp.MustCompile(`^warning: [A-Za-z0-9_.+:-]+ is up to date -- skipping$`),
```

The `Why:` prose gains a sentence recording the epoch syntax, so the colon does not read as
punctuation someone can tidy away later.

## How tested

**1. Root cause, measured on a live bed — not inferred from the regex.**
`charly check run check-cstream-pod` reported `[image-build] PASS [warnings=18 allowlisted=16]`.
Dumping the run's `summary.yml` and listing every diagnostic block with no `allowlisted:` key
returns exactly one distinct entry:

```
$ <list every non-allowlisted diagnostic in summary.yml>
text: "warning: rust-N:N.N.N-N.N is up to date -- skipping"
```

while the identical sentence for four other packages **was** allowlisted in the same run:

```
allowlisted: pacman-needed-package-already-current   text: "warning: libcap-N.N-N.N is up to date -- skipping"
allowlisted: pacman-needed-package-already-current   text: "warning: git-N.N.N-N.N is up to date -- skipping"
allowlisted: pacman-needed-package-already-current   text: "warning: pam-N.N.N-N.N is up to date -- skipping"
allowlisted: pacman-needed-package-already-current   text: "warning: shadow-N.N.N.archN-N.N is up to date -- skipping"
```

Same sentence, same cause, opposite verdict — and the only difference between them is the epoch.


Then a **fresh-rebuild** bed run (images removed and the candy version bumped first, so the
pacman layer genuinely re-executes rather than replaying cache — `cache=10/74`, 3m19s):
