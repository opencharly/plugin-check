# 2026.250.0150 — fix(check): gather the deliberately-stopped holder root in the pod live-gather (post-unroll identity semantics)

## Summary

The migrate unroll (Cutover C) promotes the first group member to the BED ROOT — for the preempt beds that root IS the preemptible holder, gracefully stopped by the claimant member's own `charly start` DURING bring-up. The pod live-gather's hard running-root gate (`deploykit.ResolveContainer` → `kit.ContainerRunning`, "container %s is not running") never fired on the old-world group root (it had NO container) but now fails every converted preempt bed (`check-preempt-live-pod` class) at the `check live` step, before any assertion can run.

This PR implements the live-gather root-state handling: a **DECLARED** holder root (`Preemptible.Holds`, authored on the converted tree node and seeded into the per-host overlay by `persistBedDeployOverrides`) whose container still EXISTS is stopped BY DESIGN — the stopped state IS the bed's assertion target. The gather:

1. re-resolves it WITHOUT the running gate (`resolveContainerDeclared`: the same engine + container-name synthesis as `deploykit.ResolveContainer`, gated on `kit.ContainerExists` — RUNNING OR STOPPED — instead of `ContainerRunning`),
2. reads the image identity off the stopped container via `liveDeployMetadata` (container `inspect` works on exited containers — the REAL image identity, no re-derivation),
3. merges the **AUTHORED** plans only (`podLiveGatherBakedSet` returns nil for the stopped root) — the baked set is the box's RUNNING acceptance (`live_image.go`'s contract), which a stopped root cannot answer; in the preempt shape the root authors no steps, so the honest outcome is `NoSteps` and the bed's preemption assertions run on the member gathers,
4. declares the stopped state in the step header (`stopped — declared preemptible holder: the preemption target state`).

Every other resolve failure — a crashed UNDECLARED root, a missing container — stays a hard error, never a silent skip. The discriminator checks `Preemptible.Holds` (never error-string parsing); a claimant root (`requires_exclusive`) is NOT a holder — it stops others and keeps running, so its gate is unchanged.

Also re-pins the Cutover C settled contracts: spec v0.2026249.2215 + sdk v0.2026249.2239.

Companion scope note (R2 disposition): the OTHER post-unroll identity seam — `${HOST:<member>}` references and preempt assertion strings naming the OLD member identities — is the converted YAML's assertion surface and updates to the ROOT identities in the DISTRO conversion PRs (arch/cachyos/fedora) as the mechanical consequence of the unroll rename; the migrate entry's documentation notes it. No plugin-check code change is needed for it (the resolver's by-name synthesis already resolves a ROOT-identity reference once the beds name the root).
