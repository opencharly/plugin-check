# 2026.244.1307 — feat(check): the snapshot-anchored check-run mode (§5.3.1)

## Summary

Implements the §5.3.1 snapshot-anchored check-run mode in candy/plugin-check (the omarchy PR-evaluation plan's batch accelerator): `charly check run <bed> --anchor <name>` reverts the golden-disk snapshot BEFORE the checks run and skips the fresh-update re-verify gate (revert IS the freshness mechanism), so a batch of PR runs shares ONE golden disk (revert ≈ seconds vs fresh install ≈ 20-30 min).

- **`--anchor <name>`** — revert-before-checks via `charly vm snapshot revert <VMTemplate> <anchor> --domain <BedDomain>` (issued through the existing `step()` helper, recorded as `snapshot-revert.log` + a summary entry). The revert targets the bed's per-deploy domain (--domain, #33/P33): the snapshot surface is keyed on the entity, and the bed's live domain is named after the DEPLOY, not the entity. A missing snapshot fails with guidance to run the FRESH lane first. Anchored mode also SKIPS the pre-run `vm destroy` for the VM arm (keeps the venue) and suppresses the Step-5 fresh-update gate (dual-layer: flag derivation + structural guard in `runCheckBed`).
- **`snapshot: on_finalize` capture** — the FRESH lane (no `--anchor`) captures the golden snapshot at install finalize per the bed's `snapshot:` policy (`on_finalize: <name>`), targeting the bed's per-deploy domain. `consistent: true` drives the quiesced `create-consistent` verb; `mode:` passes through. Idempotent: an already-captured baseline (a re-run of the fresh lane) skips with a note.
- **`--keep-venue`** — keep the VM between batch runs (forces `opts.Keep`).
- **`--var key=value`** (repeatable) — per-run variable passthrough; rides the check-live cli-reentry argv (sorted keys → deterministic argv) into `CheckRunRequest.Vars` and merges into the runner env (operator passthrough wins) on all 4 live arms + 2 feature arms + the nested-in-VM guest delegation.

Spec pin bumped v0.2026232.520 → v0.2026244.1013 (the merged anchored `CheckRunRequest` fields + `Snapshot`/`Variants` deploy fields).
