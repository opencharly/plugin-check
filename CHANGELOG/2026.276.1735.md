# 2026.276.1735 — fix(check): reclaim a plain disposable VM bed's state dir at teardown (#73)

## Summary

The disposable-bed runner's **final** teardown reclaimed the VM **domain** but never the per-domain HOST state dir, so a **plain disposable VM bed leaked its overlay every run**:

`candy/plugin-check/bed_run.go` tore a VM bed down with
`step("cleanup", "vm", "destroy", d.VMTemplate, "--domain", d.BedDomain, "--if-exists")`
— **no `--disk`** — so `$VmStateRoot/charly-<BedDomain>/` (the per-run `disk.qcow2` overlay + seed + ssh keys) survived every run.

Measured: three `check-r10-two-vm` runs (a plain disposable VM bed — no `snapshot:` policy, no `keep_venue`) left `~/.local/share/charly/vm/charly-check-r10-two-vm` at **252M**, while the bed's own `cleanup` reported PASS. Across beds this is the same accumulation class that left `~/.local/share/charly/vm` at **86G** on this host.

## Why no-`--disk` is (mostly) right — and the exact gap

The state dir MUST survive for three cases, so a blanket `--disk` is wrong:
- **golden capture** — `capturesGolden` (fresh lane + `snapshot.on_finalize`): the golden lives in `<state>/snapshots/<name>/`.
- **`keep_venue`** — the venue is kept between batch runs.
- **anchored (`--anchor`)** — the venue is reverted to the golden.

A **plain disposable bed** is none of these and rebuilds its overlay on every `vm create`, so the retained dir is pure litter.

## Change

- `bed_run.go` — extract `bedReclaimsVmStateDir(d, opts, snap)` (`d.IsVM && !opts.Keep && opts.Anchor == "" && !capturesGolden(...)`) and `vmBedDestroyArgs(...)`, which appends `--disk` to the final teardown **only** when the state dir is not needed. The VM cleanup step now calls `vmBedDestroyArgs`. The pre-run cleanup keeps its no-`--disk` form (it runs before the run's overlay exists).
- `bed_keeper_stop_test.go` — `TestBedReclaimsVmStateDir`, `TestVmBedDestroyArgs`.

Safe now that **plugin-vm#64/#65** landed: `vm destroy <entity> --domain <domain> --disk` reclaims **exactly** the per-domain state dir and never the shared entity base.
