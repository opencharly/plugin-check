# 2026.331.2239 — fix(bed): write summary.yml atomically so a partial write cannot destroy the verdict

## Summary

`writeBedSummary` wrote the run's verdict with a plain `os.WriteFile`, and the error was only printed to stderr while the caller carried on believing a summary existed. A short write — a full filesystem, a killed process — therefore leaves a **truncated `summary.yml` that no YAML reader can parse**, destroying the run's machine-readable verdict *and* taking the failing step's stderr with it.

Measured (opencharly/charly#1308):

```
$ sed -n 214,219p summary.yml
        text: "tmux star
$ python3 -c "import yaml; yaml.safe_load(open('summary.yml'))"
yaml.scanner.ScannerError: found unexpected end of stream (line 217, column 25)
$ wc -l summary.yml
218 summary.yml
```

`yamlScalar` is correct (`strconv.Quote`), so this was never an escaping bug: the file simply **ends mid-write**.

Now the write is atomic — temp file in the SAME directory (rename(2) is only atomic within one filesystem), `fsync`, `rename` — so the target is either the complete new document or the previous one, and the real error is returned rather than swallowed.

The parent asserts the PREVIOUS document is intact. Red arm — the child using the old `os.WriteFile`:


So the change is now distinguished by a test that FAILS on the unmodified code: `os.WriteFile` truncates the target, the atomic path leaves the previous document intact.

### Spike

**RCA claim:** the summary was cut off in the WRITE, not mis-quoted.

- **A. Atomic temp+fsync+rename (chosen).** Proven by the test: complete content, no temp residue, error surfaced.
- **B. Escape/quote the scalar harder.** Spiked with the artifact: `yamlScalar` already uses `strconv.Quote`, and the file does not end at a broken quote — it ends mid-document, so there are no bytes to escape:

  ```
  $ wc -l summary.yml
  218 summary.yml
  $ tail -1 summary.yml
          text: "tmux star
  ```

  An unterminated `"` from `strconv.Quote` is impossible (it always closes); a file that stops after 218 lines is a short WRITE. Eliminated by measurement.
- **C. Keep `os.WriteFile` but check `len(written)`.** Spiked with the new regression instrument — the child process writing through the OLD call under `RLIMIT_FSIZE`:

  ```
  $ PLUGIN_CHECK_ATOMIC_OLD=1 go test . -run TestWriteFileAtomic_SurvivesAShortWrite -count=1
  --- FAIL: TestWriteFileAtomic_SurvivesAShortWrite (0.01s)
      atomic_write_rlimit_test.go:62: the previous document was destroyed by a short write:
  FAIL
  ```

  `os.WriteFile` opens the target with O_TRUNC, so the short write leaves a destroyed document in place — checking `len(written)` afterwards cannot restore it. Eliminated by measurement.

**Winner:** A.
