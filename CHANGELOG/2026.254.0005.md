# 2026.254.0005 — fix: expand plan includes in the live-gather path + thread the run dir as CHECK_RUN_DIR

## Summary

The include-splicer (`expandPlanIncludes`) was applied only in the check-project projection (iterate/score/AI paths); the live-gather path that `charly check run <bed>` executes collected the RAW plan and never spliced includes, so `include:` steps hit the runUnit no-op guard and were reported SKIP — the referenced steps never executed. This broke the eval-omarchy acceptance beds' recording wrapper (the rec-start/rec-stop steps never ran, so no evidence was produced).

This PR:
- **candy/plugin-check/live_gather.go**: applies `expandPlanIncludes` best-effort in all three live arms (`pluginLoadVmCheckPlans`, `pluginCheckLivePod`, `pluginRunLocalDeployScopePlan`) — an unresolvable include keeps the raw plan.
- **candy/plugin-check/bed_run.go**: threads the run dir into the check-live env as `CHECK_RUN_DIR` (so plan steps can write into the run's `evidence/`), and creates `<logDir>/evidence/` up front (the artifact-writing verbs do no MkdirAll of their own).
