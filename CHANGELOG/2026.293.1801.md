# 2026.293.1801 — fix(check): carry the build-sized idle window to every build call site

## Summary

Head `1e028a54e66146a1b405013458e7f95c7af92f9d`.

The #123 fix handed the ROOT `image-build` step a build-sized idle window (`stepEnv(…, buildStepEnv(), …)` → `CHARLY_READINESS_NO_PROGRESS=30m`) so a cold distro-base build is not killed by the 120s probe never-hang bound. **Four** more build call sites still inherited that bound and could die the same way:

| site | before | after |
|---|---|---|
| member `image-build-<member>` | `step(…)` | `stepEnv(…, buildStepEnv(), …)` |
| member `vm-build-<member>` | `step(…)` | `stepEnv(…, buildStepEnv(), …)` |
| root `vm-build` | `step(…)` | `stepEnv(…, buildStepEnv(), …)` |
| `update-image-<member>` (the fresh-rebuild gate's member rebuild) | `step(…)` | `stepEnv(…, buildStepEnv(), …)` |

All four now use the ONE seam, so every build the runner starts gets the same 30m no-progress window; nothing sleeps, retries, or suppresses. This is the fix plan filed as plugin-check#125.
