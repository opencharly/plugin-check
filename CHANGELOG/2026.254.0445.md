# 2026.254.0445 — feat(check): thread the run calver + bed short name as CALVER/BED runtime vars (G-2)

## Summary

G-2 of the media-path authoring goal: the bed runner already threads the run dir into the check-live env as `${CHECK_RUN_DIR}` (#42); this PR threads `${CALVER}` (the run calver — the run dir's basename, single-sourced in `bedSetup`: `logDir = filepath.Join(".check", bed, calver)`) and `${BED}` (the bed's media-stage short name, e.g. `agents` for `check-omarchy-accept-agents` — derived from the check entity name the same way the omarchy acceptance suite names its staged media dirs, `accept-<short>-<calver>`) right alongside it. All three ride the SAME seam: `checkLiveTree` → `--var KEY=value` argv → `CheckRunRequest.Vars` → `withRunVars` → the runner env → `ExpandOpVars`, across every live arm (VM / pod / local — all three arms merge `req.Vars`).

An authored plan step can now write its FINAL media path directly — e.g. an artifact string of `media/${CALVER}/${BED}/${BED}.cast` — with no shell derivation and no later move. eval-omarchy is untouched here.

Changes:
- **candy/plugin-check/bed_run.go**: the `checkLiveTree` var assembly is factored into `checkRunVars` (operator `--var` passthrough preserved; the run-derived vars are authoritative — a caller-supplied value would point at the wrong run), plus `bedShortName` (deterministic, total, empty-string safe).
- **candy/plugin-check/bed_run_vars_test.go**: unit gate — the short-name derivation table, the var-map threading (operator vars preserved, nil/empty safe), and the money test: an authored `media/${CALVER}/${BED}/${BED}.cast` artifact resolves through the EXACT chain the runner applies (`checkRunVars` → `withRunVars` over the VM- and pod-venue base envs → `ExpandTestVars`) with no unresolved refs.
