# 2026.295.1159 — fix(check): build a nested child's deploy key from its root

## Summary

Fixes #127: a bed whose root is **not namespaced** could not deploy a nested child member. `bedAdd` handed the whole `<root>.<child>` roster address to `deployKeyForBed`, which splits at the FIRST dot. That dot is the namespace boundary only for a namespaced root; for a non-namespaced root it is the root/child boundary, so `check-containerd-vm.check-containerd-vm-member` became the nonexistent key `check-containerd-vm/check-containerd-vm-member` and the bed failed at `deploy add` **before any check ran**.

The mechanism fix converts the ROOT with `deployKeyForBed` and **then** appends the child, via one new `bedAddChild(root, child, tag)` helper used by all five nested-child deploy/redeploy call sites (VM `LocalChildKeys`, kubevirt `ChildKeys`, the pod arm's `ChildKeys`, and both fresh-rebuild redeploy loops). The namespaced-root arm is unchanged: `openclaw.check-openclaw-pod` + `child` still yields `openclaw/check-openclaw-pod.child`.

The missing control named in the issue is closed: the new test asserts the **whole argv** for a non-namespaced root with a nested child, and the namespaced arm is asserted alongside it.
