# 2026.272.1732 — fix(check): pin the capture session's working directory to the project root

## Summary

Fix the appium/capture-recorder evidence-row split by pinning the transient capture session's working directory to the project root.

A capture recorder is spawned by `spawnSystemdUnit` as a `systemd-run --user --collect --unit charly-capture-<id>` transient unit. A `--user` transient unit's `ExecStart` runs under the **user systemd manager's own default `WorkingDirectory`** — the user's home — never the caller's cwd. The recorder's `state_dir` / `artifact_dir` are the run's **relative** `.check/<bed>/<calver>/...` paths (the appium provider passes `CHARLY_APPIUM_STATE_DIR` / `CHARLY_APPIUM_ARTIFACT_DIR` straight from the runner envelope), so the recorder wrote its `row.json` / `FINAL` marker / pulled MP4 under `$HOME/.check/...` while the check runner polled the worktree-relative `.check/...`. The evidence row appeared "missing"; the prior session bridged it with a `.check` symlink.

`cmd.Dir` could not fix this — it sets the **`systemd-run` client's** cwd, and the client exits immediately; the detached unit's cwd is controlled only by `WorkingDirectory=`. This change passes `--working-directory=<abs cwd>` (the runner's project root, the root every relative `.check/` path resolves against — `main.go`'s `os.Chdir(cli.Dir)` has already run), and absolutizes `opts.Dir` when a caller supplies one.

This is the identical bug class and the identical primitive already fixed in `candy/plugin-fleet/ephemeral.go` (`registerTransientTimerArgs` → `--working-directory=`, RCA at lines 250-258, regression test `TestRegisterTransientTimerArgs_PinsWorkingDirectory`).
