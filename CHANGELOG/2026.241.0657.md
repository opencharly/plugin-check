# 2026.241.0657 — fix(check): surface CHARLY_REPO_OVERRIDE in the bed verdict (issue #340)

## Summary

A bed run auto-appends a `CHARLY_REPO_OVERRIDE` pair (`SelfSuperprojectOverridePair` in `spec/proc/repo_override.go`) pointing the parent superproject's `@github` refs at the local working tree, **ignoring the `:vTAG`**. The final verdict line and `summary.yml` now name the active pair, so a reader (including the next validator) knows the verdict is about the **LOCAL tree, not the PR head** — closing the silent divergence opencharly/charly#340 describes.

Changes:
- `bedRunResult.RepoOverride` — the auto-added pair, populated from the bed session
- `bedVerdictLine()` — the final `charly check run` verdict names the override when active
- `writeBedSummary` — `summary.yml` carries a `repo_override:` line
- `bed_override_test.go` — pins both surfaces
