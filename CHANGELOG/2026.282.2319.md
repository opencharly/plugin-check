# 2026.282.2319 — feat(check): the bed record says when a step SKIPPED — summary.yml carried only ok: (a skipped phase read exactly like a passing one)

## Summary

`opencharly/plugin-check#93` — **the same defect class as `charly#865`, one layer up.** `writeBedSummary` emitted `name` / `duration_seconds` / `ok` per step, so a phase that **SKIPPED** its assertions was written exactly like one that asserted and passed: `ok: true` either way. The counts existed at the moment the phase finished — `spec/report` prints `N step(s): X passed, Y failed, Z skipped` — and were simply not carried into the record a later reader reads.

### Traced first, as the issue asked

A bed step's `OK` comes from **three** sites: the whole-bed prerequisite skip (`:511`), a plain step (`:702`, `OK: err == nil`) and a **phase** (`:737`):

```go
ok := cerr == nil && reply.ExitCode == 0 && diagFail == ""
```

and `stepResult` carried `Name`/`Duration`/`OK`/`Diag` **and nothing else** — so there was no step-level skip input at all, and no field that could hold one. The phase branch already has the rollup text in hand: it scans the **same** `logText` for diagnostics one line before it decides `ok`.

### The change

- `skippedFromRollup` parses that line — anchored on the `", Z skipped"` tail, so a step *named* something-with-skipped-in-it cannot be read as a count (`TestSkippedFromRollup` pins both the counts and that non-count).
- `stepResult` gained `Skipped int`.
- `writeBedSummary` emits `skipped: N` for **every** step — like `ok:` itself, because a reader must be able to tell *"this step skipped nothing"* from *"this record predates the field"*.

**Additive by design:** `summary.yml` has **no** `status:` word to change, so the concern in the issue — a verdict word that a consumer matches on — does not arise. The issue's second half is answered by there being no field to change.

**`check-live`: `ok: true` AND `skipped: 1`.** The phase asserted nothing and the bed passed — and before this change the record said only `ok: true`, which is indistinguishable from a phase that ran and passed. The full file (with its diagnostics and allowlist blocks) is archived at `.dsh/ledger/org-triage-2026-10-09/evidence/box95-witness/summary-skip-witness-RAW.yml`, and the fixture at `fixture-skip-witness-bed.yml`.

**Every step is `ok: true`; there is no failed step.** The first version of this body pasted an excerpt of a *different* run — one whose live phase also carried a step affected by a second change in the same harness — and pasted it through a `sed` range that silently dropped `duration_seconds` from two steps, so it neither matched the writer nor demonstrated the claim. **Both were my errors, and the reviewer was right to reject them.** This witness has exactly one plan step, so there is nothing to explain away.

**The writer is now covered too** (`TestWriteBedSummaryEmitsSkipped`), and **proven able to fail**:

```console
$ go test ./... -run TestWriteBedSummaryEmitsSkipped -count=1     # --- PASS
$ sed -i '/skipped: %d/d' bed_run.go && go test ...               # --- FAIL
```

so the emission cannot be deleted without a test going red.

**Scope stated honestly, as the issue did:** this is a **reporting** gap, not a verification gap — the counts were always in `check-live.log`, so the evidence was recoverable. What changes is that the *summary* stops understating. That is why it is a separate change rather than folded into `#865`.
