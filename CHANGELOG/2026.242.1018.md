# 2026.242.1018 — feat(diagnostics): allowlist the snapshot-alignment downgrade

## Summary

pacman prints

```
warning: openssl: downgrading from version 3.6.4-1 to version 3.6.3-1
```

when a **configured repository serves an older version than the one installed** and the
transaction was asked to allow that (`-Syuu`).

For a distro whose identity **is** a frozen snapshot of an upstream repository, that is the
**intended and correct outcome, not a fault**. The base container image ships packages at
upstream's current versions, the distro pins an older set on purpose, and aligning the image
onto it necessarily downgrades.

### Every file in the diff

| File | What changed |
|---|---|
| `candy/plugin-check/bed_diagnostics.go` | a `pacman-repo-serves-older-than-installed` warning-tier entry |
| `candy/plugin-check/bed_diagnostics_test.go` | the real-lines case and the over-claim guards |

### The case in hand

`layer-omarchy-base` repoints pacman at `stable-mirror.omarchy.org` and runs `-Syuu`
precisely so the image **is** that snapshot rather than a **mix of two** — the silent defect
that alignment exists to remove, where five packages preinstalled in the Arch base sat newer
than Omarchy's frozen mirror and pacman never downgrades on its own.

So a build producing **none** of these lines would mean the alignment had not run.
Suppressing them at the source would suppress the evidence. But leaving them counted makes
every Omarchy bed carry five permanent warnings **for doing the right thing**.

There is nothing for charly to fix at either end: refusing the downgrade leaves the image a
version mix, and pacman has no quieter way to say it did what it was asked. That is the same
shape as the `--needed` entry directly below this one — two correct behaviours meeting, and
pacman saying so.

### Deliberately narrow

The pattern is the exact per-package sentence, anchored at both ends, matching the
`pacman-needed-package-already-current` entry's scoping so a multi-line pacman warning cannot
hide behind it. The version class includes `:` because pacman renders an epoch as
`<epoch>:<ver>-<rel>` — the same gap that let 721 of 15,598 Arch packages escape the
`--needed` entry until it was fixed.

It claims only the warning sentence. It does **not** claim `error:` lines, and it does not
claim a downgrade that **fails** — a failed transaction still reports its own error and still
reds the step.

### ZERO warnings — one run, reconciled line by line

`check-omarchy-cstream-pod`, cold (`cache=11/136`), read from its own
`.check/<bed>/<ts>/summary.yml`:

```
[image-build] PASS after 7m59.76s [allowlisted=34 cache=11/136]
```

No `warnings=` field at all. The per-rule accounting:

```
sample finding keys: ['allowlisted', 'count', 'first_line', 'pattern', 'severity', 'text']

rule                                            shapes    lines
dev-worktree-binary-notice                           1        1
pacman-needed-package-already-current               25       26
pacman-pacnew-config-notice                          2        2
pacman-repo-serves-older-than-installed              5        5
TOTAL                                               33       34

step counters: errors=0 warnings=0 allowlisted=34
```

**errors=0, warnings=0, zero counted lines.**

**Why 33 and 34 are both right.** An earlier revision of this body reported the rule
breakdown as `33` against a counter of `34` and was correctly blocked as inconsistent. The
resolution is that `summary.yml`'s `findings:` list holds **distinct SHAPES**, not raw lines
— `shapes()` in `bed_diagnostics.go` collapses them, and each entry carries a `count`:

> *"Fifty-one identical scriptlet refusals are ONE shape seen 51 times, which is what a
> reader needs; the raw 51 lines are in the log the summary points at."*

So **33 shapes = 34 lines**, because two `is up to date -- skipping` lines normalise to one
shape. The counter was never wrong; the earlier summation counted the wrong unit. The table
above now reports both columns so the two numbers reconcile on their face.

| Rule | Lines | What it claims |
|---|---|---|
| `pacman-needed-package-already-current` | 26 | pacman noting `--needed` skipped an already-current package |
| `pacman-repo-serves-older-than-installed` | 5 | the snapshot alignment downgrading onto Omarchy's frozen mirror — the intended effect |
| `pacman-pacnew-config-notice` | 2 | a `.pacnew` written beside a config pacman did not overwrite |
| `dev-worktree-binary-notice` | 1 | charly confirming the binary came from `task build:binary`, which is what R9 requires of this evidence |

Getting to zero took three **source** fixes rather than three allowlist entries for one
symptom:

1. **`plugin-check`'s `--needed` rule excluded `:`**, so every **epoch**-versioned package
   escaped it — **721 of the 15,598 packages** in these repositories. Already fixed upstream;
   charly pinned a stale version.
2. **charly's `arch` bootstrap omitted `--needed`**, reinstalling curl and ca-certificates on
   every Arch-family build — measured 2 → 0 in
   [charly#481](https://github.com/opencharly/charly/pull/481), merged.
3. **The snapshot-alignment downgrade had no rule.** A correct, intended behaviour with no
   quieter spelling, so it earned one in
   [plugin-check#10](https://github.com/opencharly/plugin-check/pull/10) — narrow, and tested
   not to claim a failed transaction.
