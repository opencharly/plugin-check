# 2026.268.1841 — feat(check)!: per-bed RunEnv isolation + namespace-aware bed refs

## Summary of changes

Retire the check-bed roster's **process-global `os.Setenv` isolation** in favour of
explicit per-invocation data, and resolve namespaced beds end to end
(plan §4.2 / F8; RCA issues 1, 3, 5, 6, 7). Adopts the merged
`sdk v0.2026268.1823` + `spec v0.2026268.1800`. This is the plugin-check leg of the
`check-bed-roster` cutover.

### What changed
- **`bed_session.go`** — `bedSetup` builds a per-bed `spec.RunEnv` (its own
  `CHARLY_DEPLOY_CONFIG` temp overlay + repo override), derives `bedCtx`, and returns
  it; `runCheckBed` adopts `bedCtx` for the whole run. Every `os.Setenv`/`os.Unsetenv`
  for the three isolation vars is **deleted**. The preempt-lease marker is a
  per-invocation map entry (`arbiterAcquire` takes the env), never process env. The
  per-bed temp dir is created before the session exists, so a `defer` removes it on
  every pre-session early return (load error / no charly.yml / not-a-bed / GPU-prereq
  skip); once the session is built it ADOPTS the dir and teardown is the sole remover
  (no leak).
- **`command.go`** — `bedCliReq` threads the run env to each forked child via
  `spec.CliRequest.Env` (`childEnvForReq`), so a child sees only its own bed.
- **`bed_run.go`** — `bedSetup`'s isolated ctx is adopted; `TearDownMembers` /
  `BringUpMembers` / `persistBedDeployOverridePluginSide` receive ctx (so member forks
  write the bed's overlay — RCA issue 7); `bedArtifactRef` maps a bed's CONFIG image
  ref to the ARTIFACT-space leaf `charly check box` resolves (the two reference
  spaces — RCA issue 6); `printDebugRetentionNotice` takes the repo override from the
  RESULT, not process env.
- **`checkproject.go`** — replaces the root-only `rp.Deploy[entity]` lookup with the ONE
  namespace-aware resolver `spec.UnifiedFile.ResolveBed(entity)` (falling back to the
  envelope only for a non-bed root entity), so a qualified bed classifies (IsBed/HasIterate)
  the same way it validates and runs (RCA issue 3).
- **`bed_session.go`** — the bed RUN path resolves via
  `spec.UnifiedFile.ResolveBedForRoot(bed)`, which additionally root-qualifies the bed's
  namespace-local `image:`/`from:` (and every member's) so `charly box build`/`deploy add`
  from the project root resolve them (RCA issue 5). `bedArtifactRef`
  (above) then maps those config refs to the artifact-space name `charly check box` uses
  (RCA issue 6).

### Tests
- `bed_session_env_test.go` — 400 goroutines prove concurrent in-process beds are
  isolated (no env bleed); `TestChildEnvForReq_*` pins the child-env threading;
  `TestArbiterAcquire_LeaseMarkerIsPerInvocation` drives the REAL `arbiterAcquire` path
  (via a stubbed arbiter seam) to prove the lease marker is per-invocation data —
  it fails if the acquire reads/writes process env.
- `bed_run_test.go` — `TestBedArtifactRef_MapsConfigRefToArtifactSpace`.
- `checkproject_test.go` — `TestClassifyCheckProjection_QualifiedBedClassifiesAsBed`
  (the qualified-bed classification path, RCA issue 3).
