# 2026.269.2342 — fix(check): classify a namespace-qualified bed's venue from uf.Beds()

## Summary

Classify a namespace-qualified bed's venue from `uf.Beds()` — a narrow seam that
supersedes the withdrawn opencharly/sdk#308.

`charly check live <ns.bed>` from the umbrella root failed:

```
charly: error: command "check": container charly-charly.check-charly-vm is not running
```

because the resolved-project envelope's `Deploy` holds only ROOT-level deploys, so
at a superproject whose beds live in an imported namespace (the umbrella root
`import: charly: ./charly`) the classification tree is EMPTY and the VM venue is
never seen.

`checkClassificationTree` folds the namespace-qualified beds (`uf.Beds()`) into the
CHECK-CLASSIFICATION tree **only**. The envelope's `Deploy` is NOT mutated: the
build's validate step iterates it, and folding beds there (sdk#308) made a foreign
build context validate another namespace's beds:

```
deployment "charly.check-task": kind:local template "check-task-app" not found
```

Companion to opencharly/plugin-check#61 (exact-key-first qualified lookup), which
is merged.

`TestMergeBedsIntoTree` (new) pins the fold: a nil classification tree plus the beds
yields the qualified bed, and a ROOT-level entry wins a key collision.
