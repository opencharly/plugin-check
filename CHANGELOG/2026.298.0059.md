# 2026.298.0059 — fix(check): a declared check that skips is a SKIP, not a PASS (#132)

## Summary

A bed run whose **declared check skipped** reported `PASS (steps=N)`, exited 0, and wrote a
`summary.yml` whose steps all read `ok: true` — so the acceptance record could not say that
the run proved nothing. That is the product half of opencharly/charly#904; **this repo owns
the bed runner, the summary writer and the verdict line**, so the fix lands here
(opencharly/plugin-check#132).

**The diff, file by file.**

| file | what it carries |
|---|---|
| `candy/plugin-check/bed_status.go` (new) | the verdict vocabulary (`PASS`/`SKIP`/`FAIL`) and the reader of the child's own report — the only place the per-check ids, statuses and reasons exist |
| `candy/plugin-check/bed_run.go` | the step's own verdict, the per-check record, and the `summary.yml` fields (`status:`, `checks:`, `skipped_checks:`); the boolean `summaryStatus` is deleted here |
| `candy/plugin-check/run_cmd.go` | the verdict line and the verdict → exit-code mapping (`3` = skip, `2` = checks failed, `1` = infra) |
| `candy/plugin-check/roster.go` | the roster's own bucket for a bed that ran and proved nothing |
| `candy/plugin-check/bed_status_test.go` (new) | the per-check reader, the three-state verdict, the vacuous-phase rule, the exit-code mapping, the headline shape, the record's per-check block, the roster's unproven bucket |
| `candy/plugin-check/bed_override_test.go` | the verdict-line fixture updated for the new signature — a run that proved something now says WHICH check proved it |
| `candy/plugin-check/bed_summary_writer_test.go` | the record fixture updated for the new `status:` line |
| `charly.yml` | the two R10 witness beds |

The skip was captured **one layer below the verdict**: the engine's own rollup count was
already in the record (`skipped: 1` on the step), but the run's verdict was derived from a
**boolean** (`summaryStatus(ok bool)` → `PASS`/`FAIL`), so the count never reached it.

This change:

- gives the run a **three-state verdict computed from the per-check statuses**
  (`bed_status.go`, new): `PASS` (the run proved what it declared) / `SKIP` (the run
  completed but proved **nothing**) / `FAIL` (a check failed, or the run could not complete);
- **records the per-check statuses** in `summary.yml` (`checks:` — the id, the status, the
  text, the reason), a per-step and per-run `status:`, and a run-level `skipped_checks:`.
  `ok:` keeps its **one** meaning — NO FAILURE — so every existing reader of it is unaffected;
- makes the **headline unable to read as a bare PASS**: a run that proved nothing says
  `SKIP`; a run that proved something carries the count of the declared checks that did not
  run and names each one with the reason the child's report gave;
- maps the `SKIP` verdict to **exit code 3** (`CheckSkippedExitCode` — "not a verdict",
  which the org's own `scripts/check-bed-watch.sh` already classifies as *"a SKIP, never a
  pass"*). A `FAIL` still wins over a `SKIP`, and the bed still completes and tears down as
  it would after a pass;
- gives the **roster** its own bucket: a bed that ran and proved nothing is neither a
  failure nor a pass, and the roster says `SKIP`.

The verdict reads **what the run proved**, not "any skipped check". A plan may declare a
check that does not apply to its substrate — `skip: true` and `exclude_distro:` are
documented authoring features (layer-charly-check/charly.yml:1902-1903), and the org's own
images carry them (layer-dev-tools/charly.yml:142-166 declares three `exclude_distro:`
checks) — so a phase that passed at least one check is a `PASS`, and the checks that did not
run are recorded **per check**. A phase that asserted nothing (no plan steps at all) declares
**no check id**, so it cannot unprove a check another phase proved: it is recorded as a
`SKIP` step and named in the headline. That is what keeps the pre-existing #110 witness bed
(`check-empty-resolution-witness`) a `PASS` — see the R1 note below.

`Closes #132`. The consumer-facing issue opencharly/charly#904 closes with the charly leg
(the pin bump that carries this fix into the charly binary).

## How tested

**The R10 gate — the two witness beds, by name.** Both are `disposable: true` `kind: local`
beds driven by `charly check run`, so each run is the full sequence (build → deploy → check
live → fresh `charly update` → tear down):

1. `check-skip-verdict-witness` — the bed whose verdict is watched; its only declared check
   is authored `skip: true`, so the phase proves nothing.
2. `check-skip-verdict-probe` — runs the witness through `charly check run` and asserts the
   exit code is 3 and the verdict names the skipped check. **This is the discriminating
