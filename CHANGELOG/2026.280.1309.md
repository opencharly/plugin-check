# 2026.280.1309 — fix(check): resolve a dotted local bed with the dispatcher's resolver (#78)

## Summary

`charly check live <dotted local bed>` failed **before its plan ran** with `check live: local deployment "<name>" not found`, for a bed `charly deploy add <name>` resolves fine (opencharly/plugin-check#78).

Two divergent resolvers, one name shape:

- the **dispatcher** (`checkLocalTarget`) resolved the name via `resolveDeployNodeByPath` (exact-key-first), so it correctly picked the local arm;
- the **local arm** (`pluginCheckLiveLocal`) then re-resolved the SAME name with the in-substrate-only `resolveNestedNode`, which cannot reach a **namespace-qualified** deploy key (`charly.check-task` — its dots are namespace separators, not a member path). It returned nil → "not found".

The fix makes the local arm use the dispatcher's resolver:

- `resolveLocalDeployNode` (new, `venue.go`) — `resolveDeployNodeByPath` + the correct root (the node itself for an exact-key match; the first segment for a genuine member path). One resolver per name shape (R3).
- `pluginCheckLiveLocal` (`live_gather.go`) — uses it (`dotted` at line 547 stays live for `ResolveDeployChain`).
- **the R10 witness** — `charly.yml` imports `testdata/dotted-local-fixture` as the namespace `dottedfix`, so that project's bed is reachable ONLY as the namespace-qualified `dottedfix.dottedfix-bed`; the new disposable bed `check-dotted-local-resolve` drives a real `charly check live` against it and asserts the fixture step id.
- the stale header comment in `charly.yml` ("This file declares no entities of its own") is corrected — false since the import and the witness entities were added.

**Correction to the previous body.** It routed the in-repo-bed impossibility to `opencharly/charly#330` — the right number in the wrong repo. `opencharly/charly#330` is CLOSED and unrelated (pixelflux/ffmpeg); the real OPEN issue is **opencharly/opencharly#330**. That issue is now fixed by two merged producer PRs, which is what makes this shape possible at all: **opencharly/spec#202** (tag `v0.2026280.1255` — an import ref's identity names its PROJECT, so a subdirectory project mounts as a definition instead of resolving to a self-reference) and **opencharly/sdk#350** (tag `v0.2026280.1251` — the materialized wire codec terminates the cyclic namespace graph).

**One change was split out, not dropped.** The earlier revision of this branch also changed `checkLocalTarget`'s dispatch for a RESOLVED non-host leaf under a HOST root. That alters a DIFFERENT behavior; the local-bed R10 cannot distinguish it (this bed's leaf is host-venue, so both forms return identically), and its only witness was a unit case. It is separable — this cutover's R10 passes and proves its claim WITHOUT it — so it now lives in its own named change, **opencharly/plugin-check#86**, which must carry a runtime witness bed. Nothing is silently discarded; the issue states the exact diff and why the witness needs a different composition.

Closes opencharly/plugin-check#78.
