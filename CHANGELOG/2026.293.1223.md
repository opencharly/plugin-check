# 2026.293.1223 — fix(check): give the generated build steps a build-sized idle window

## Summary

Fixes **[plugin-check#123](https://github.com/opencharly/plugin-check/issues/123)**: the generated root `image-build` step now sizes the CHILD's plugin-invoke idle window to a build, instead of leaving it at the project's readiness `no_progress` probe default (90s), where an IO-bound build phase is indistinguishable from a wedged call.

**The mechanism (RCA).** The bed runner runs the build step as `charly box build` through the cli seam. The seam deliberately sets no deadline on that child (`hostBuildCli`: "the context is NOT used as a deadline") and heartbeats the CALLER's activity clock while it runs. But the CHILD is itself a `charly` process whose own plugin dispatch (plugin-build) carries the plugin-invoke idle guard, and that guard's window is the project's readiness `no_progress` — **90s by default**. A build's IO-bound phases (the OCI bridge's `podman load`, a cold layer export) make no host-visible progress for minutes, so the guard cancels the child and SIGKILLs the build:

```console
charly: error: command "build": building arch.arch-builder: bridging arch.arch-builder into the podman store: buildkitdrive: load /home/atrawog/.cache/charly/buildkitd/export/ghcr.io_opencharly_arch-builder_check-crabbox-pod-2026.293.1030.oci.tar: podman load -i /home/atrawog/.cache/charly/buildkitd/export/ghcr.io_opencharly_arch-builder_check-crabbox-pod-2026.293.1030.oci.tar: signal: killed: Getting image source signatures
charly check run check-crabbox-pod: [image-build] FAIL after 2m2.279s
```

**The fix.** The root `image-build` step passes `CHARLY_READINESS_NO_PROGRESS=30m` to the child through the seam's per-call env — `spec.CliRequest.Env`, which the host cli handler merges over the inherited environment (the seam's placement-invariant carrier). 30m stays within the default `absolute_cap` (30m), so the child's readiness ordering validates without a second override. Non-build steps keep the project's windows.

**The seam.** The diff deletes the old `bedCliCombined` wrapper (its only caller was the step runner) and makes **`bedCliCombinedEnv` the sole combined-capture seam**, carrying both the combined capture and the per-call env. Round 2 correctly flagged that this rename was not accounted for in the body; it is now.

**Scope — deliberately narrow.** Only the ROOT `image-build` call site changed: it is the one the cited bed exercises, and the one whose death was measured. The member `image-build-<member>` and `vm-build` sites were rewired in round 1 and reverted here — neither has a run that would fail without the change. They are filed as [plugin-check#125](https://github.com/opencharly/plugin-check/issues/125) with the measurement plan; the VM path is plausibly already safe because `plugin-vm` is out-of-process (its guard counts peer-tree CPU via the #699 reader), but that needs measuring, not assuming.
