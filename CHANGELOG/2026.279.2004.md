# 2026.279.2004 — fix(diagnostics): claim the grub 2.12+ 'os-prober is not installed' chroot warning (plugin-check#81)

## Summary

Claim the second os-prober-absent warning the pacstrap-chroot `grub` build emits, so
the `vm-build` step of a bootstrap-VM bed no longer reports a surviving `warnings=1`.
Fixes #81.

### The defect

The pacstrap bootstrap VM's mkinitcpio/grub build emits **two** os-prober-absent
warning lines, but the `mkinitcpio-chroot-warnings` allowance
(`candy/plugin-check/bed_diagnostics.go`) claimed only the first:

```
Warning: os-prober will not be executed to detect other bootable partitions.        # claimed before
Warning: os-prober is not installed; EFI BootNext entries will not be filtered      # NOT claimed
against detected OSes, so non-OS entries (e.g. firmware updaters) may appear in the menu.
```

The second is emitted by grub 2.12+ on the **EFI** path and describes the SAME
absent-in-chroot condition the allowance's own `Why` already names ("the chroot has no
… os-prober").

**Correction to the first body's quote.** The first body quoted that warning wrapped
across two physical lines. That wrap was an artefact of the quoting, not the log. In the
real log it is a **single 173-character physical line**, so the anchored match claims it.
Pasted evidence (the live `vm-build` log,
`distro-cachyos/.check/check-dsh-cachyos-vm/2026.279.1749/vm-build.log`):

```
$ grep -n "os-prober" vm-build.log | cat -A
1124:Warning: os-prober will not be executed to detect other bootable partitions.$
1128:Warning: os-prober is not installed; EFI BootNext entries will not be filtered against detected OSes, so non-OS entries (e.g. firmware updaters) may appear in the menu.$

$ grep -n "EFI BootNext" vm-build.log | head -1 | awk '{print length}'
173

$ # the new Match alternative against the raw line:
1128: match=True 'Warning: os-prober is not installed; EFI BootNext entries will not be filtered against detected OSes, so non-OS entries (e.g. firmware updaters) may appear in the menu.'
```

### The fix

Extend the allowance's scoped `Match` to the second line verbatim — the same-condition
sibling folds into the entry that already owns it, keeping the anchored `^…$` form. The
`Why` is updated to name both grub code paths.
