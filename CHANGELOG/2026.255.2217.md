The repo has a second CI gate beside the validator: `deploy.yml` (`name: candy`) builds the PINNED charly `v2026.238.1242` and runs `charly box validate` at the repo root. On `09227cb` it FAILED (run [34718674066](https://github.com/opencharly/plugin-check/actions/runs/34718674066)):

**RCA (control-first, on a pristine `main` clone with the CI's own pinned charly):** the repo root's `charly.yml` declares `discover: {path: candy, recursive: true}` (so that the gate actually gates the candies — opencharly/charly#459). That is correct for `candy/plugin-check/charly.yml`, and wrong for a PROJECT manifest: the reproducer's file made charly look for a candy `reproducer` (its directory) that has no candy body. **Fix (no gate weakening):** the project moved out of the scanned tree, to the repository root's `testdata/pacman-mirror-abandoned/reproducer/`; the root `charly.yml` is untouched. Proof with the CI's OWN pinned charly, before and after:
