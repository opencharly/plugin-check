# 2026.279.2102 — fix(diagnostics): claim the CachyOS openssh "local newer than repo" skew (plugin-check#83)

## Summary

Claim the CachyOS `openssh` "local newer than repo" skew so a CachyOS `deploy-add` /
`update` reaches zero warnings. Fixes #83.

### The defect

The integrated `check-dsh-cachyos-vm` R10 run `2026.279.2005` surfaced a NEW
un-allowlisted warning on the SAME pacman transaction as the four already-allowlisted
skews:

```
:: Starting full system upgrade...
warning: binutils: local (2.47-4) is newer than cachyos-v3 (2.47-2)             # allowlisted
warning: libtool: local (2.6.2-5) is newer than cachyos-v3 (2.6.2-3)            # allowlisted
warning: openssh: local (10.6p1-1) is newer than cachyos-core-v3 (10.5p1-1.1)   # NOT claimed
warning: xz: local (5.8.4-1) is newer than cachyos-v3 (5.8.3-1)                # allowlisted
warning: zstd: local (1.5.7-3) is newer than cachyos-v3 (1.5.7-2)              # allowlisted
```

`openssh` is the SAME class: the published CachyOS base image installs a build NEWER
than the CachyOS repos serve, so every pacman transaction reports the local copy as
newer. The step counted `warnings=3` (the line renders 3×), red-ing an otherwise fully
green bed. Upstream drift, not something this repo changed.

### The fix

Add the per-package allowance `cachyos-openssh-local-newer-than-repo` in
`candy/plugin-check/bed_diagnostics.go`, following the documented one-package-per-entry
pattern the four sibling entries establish, with a scoped single-package `Match` (it
accepts any repo name, so the real `cachyos-core-v3` spelling claims too).
