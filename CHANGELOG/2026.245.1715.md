# 2026.245.1715 — feat(check): the whole-run recording wrap — deploy record: field splices record start/stop around the live acceptance phases

## Summary

The whole-run recording wrap (G5): a deploy `record: {terminal: true, record_name: …}` field on a check bed makes the runner splice a recording around the live acceptance phases. Three seams complete the feature:

1. **--steps-file plan source override** — the injected steps run INSTEAD of the baked plan in an isolated live invocation. One canonical `wrapStepsFileSet` helper substitutes the injected steps under the `steps-file` origin across pod/vm/local/group arms (R3); the VM arm previously ignored `req.Plan` and ran the full baked tree, duplicating the bed's own record steps and colliding on the tmux session.
2. **desugared plugin discriminator** — injected steps carry `plugin: record` (the parse-time sugar is skipped for injected steps), so the verb resolver accepts them.
3. **first-live-pass stop + manifest scan** — the R10 `charly update` phase recreates the VM domain, so the recording cannot survive to a post-rebuild stop; the wrap now brackets the install→check flow. `recordings.yml` scans the record-wrap logs so the whole-run entry lands next to summary.yml with `survived_teardown` asserted (G5 discoverability).
