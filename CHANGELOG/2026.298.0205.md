# 2026.298.0205 — fix(check): the verdict reads the child's own report, and only a plan child prints one

## Summary

A bed run's verdict could be **credited by text**. Two holes followed from that, and both
were mine to close (opencharly/plugin-check#134):

- **A PASS out of report-shaped text.** The reader collected every report-shaped line
  **anywhere in the step's log** and asked nothing about whether a report had been printed
  at all. A build whose output ended with a self-consistent report-shaped block therefore
  banked a PASS for a run whose plan proved **nothing**.
- **A report that says FAIL was not a FAIL.** The verdict counted passes and skips; it had
  no FAIL branch. A child whose own report said a declared check FAILED read as *"it
  asserted nothing"* — a SKIP, never a FAIL. The report and the exit code come from the
  same step results, so a child that honours its contract already exits 2; the hole was the
  case where it does not, and the record then carried `status: FAIL` for a check while the
  run read PASS.

**The diff, file by file.**

| file | what it carries |
|---|---|
| `candy/plugin-check/bed_status.go` | the reader: the child's **own** report (the LAST report the child printed, because the engine renders the report last), the count-agreement rule, the plan-child rule, and the FAIL branch of the verdict |
| `candy/plugin-check/bed_run.go` | the step's verdict: the report is read through the plan-child rule, and a report that says FAIL makes the step FAIL (the same class the diagnostic backstop reports as 2) |
| `candy/plugin-check/bed_status_test.go` | nine new tests, including the drift test that holds the plan-child table against this package's own source |

**The rules the reader now follows.**

1. **A report is the child's OWN report** — the last block the child printed. The engine
   renders the report last (`live_cmd.go` after any forwarded guest output, `feature_cmd.go`
   after the guest's own output), so the last rollup in the log is the report the child
   printed, and the per-check lines are the ones in the block before it.
2. **A log with no report credits nothing.** The absence of a report is not a claim that a
   check was skipped; it is the absence of a claim.
3. **A block that disagrees with its own rollup is not read.** The rollup says "N steps" and
   the block must carry N step lines. A block that does not is carrying text the report did
   not print — a step's **message** with a report-shaped line inside it, which the engine's
   `truncate()` permits because it bounds a message's length but does not flatten its
   newlines. Such a report credits nothing, and the phase says so.
4. **A report whose declared check FAILED is a FAIL** of the step, with the failed check
   named.
5. **Only a PLAN child's log can carry a report.** `planChildReporters` binds the child
   command the runner launches to the command in this package that renders that child's
   report. Every other child in a bed run — a build, a deploy, an update, a teardown —
   prints no report, so report-shaped text in its log is CONTENT. The runner knows which
   child it launched (the argv it passed), so the table — not the text — decides.

**The direction of safety is deliberate:** an unreadable report, and a report that did not
come from a plan runner, can only **withhold** a credit, never manufacture one. A run that
proved nothing stays a SKIP.

**Two seams the change had to state rather than assume.** The log the reader parses is the
child's **merged** output: the cli seam captures the child's stdout and stderr into one
text, reunited a whole line at a time, so a report cannot be told apart by the stream it
was written to — and must not be, because the runner has no other view of the child. (The
first cut of this change read "stderr only" and every live bed went red: the seam merges
the streams.) And the reader is a **text** reader, cross-repo-coupled to `spec/report`'s
rendering; the root fix — a verdict that reads the child's step RESULTS instead of a
rendering of them — is opencharly/plugin-check#135.

`Closes #134`.
