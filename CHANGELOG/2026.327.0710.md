# 2026.327.0710 — feat(check)!: a bed run asks for bed actions, and only a disposable bed may have them

## Summary

opencharly/plugin-check#153 (**G5**), the plugin leg. `charly check run`'s live stage is verify-only, so **every bed `run:` step is skipped** and a bed's actions never happen; authoring them as `check:` steps contradicts D-VERB-1. The schema field exists (`opencharly/spec#426`, `v0.2026327.605`) and the walk honours it (`opencharly/sdk#621`, `v0.2026327.625`); this leg produces and guards it.

- **`check live --bed-actions`** sets `#CheckRunRequest.bed_actions`. A plain `charly check live` stays verify-only.
- **`check run`'s live stage always asks for it** (`checkLiveArgv` → `check live <ref> --bed-actions …`), so a bed's own actions execute in authored order between its checks.
- **`bedActionsAuthorized` refuses a deployment that is not `disposable: true`** with an error naming D-DEP-3 — never a silent skip — and accepts an ephemeral deployment, which implies disposable.
- **Every live RunnerConfig arm threads the request**: pod/vm (`live_gather.go`), the local deploy-scope plan, and kubevirt. The box and instrument paths deliberately do NOT — box mode has no deployment to authorise.
