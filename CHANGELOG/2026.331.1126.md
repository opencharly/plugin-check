# 2026.331.1126 — fix(check)!: authorize a nested member's bed actions via its disposable root

## Summary

Fix the D-DEP-3 bed-actions authorization so a NESTED (in-substrate) member of a `disposable: true` bed root is authorized. A nested member runs its bed actions INSIDE its root deployment's disposal-authorized venue, so the ROOT's flag governs. `bedActionsAuthorized` previously checked only the resolved LEAF node, which does not carry the parent's flag — `FoldMembers` propagates the owner's disposability onto the folded top-level entry, not onto the nested node — so `charly check-group` (and `check-structkind`) failed `check-live-check-group-member` with D-DEP-3 after every setup step had passed. Reproduced by a new test that fails before the fix and passes after; the negative (non-disposable root + leaf) stays refused. RCA (8-step) + R12 spike round posted on opencharly/charly#1299.

### Spike

RCA (opencharly/charly#1299, 8 steps): the mechanism is `bedActionsAuthorized` authorizing off the resolved LEAF node only, which does not carry the disposable parent's flag. Candidates spiked against the real guard (throwaway `zz` spike test):

```
(a) shipped fix — parent disposability propagated in the guard, leaf not disposable: err=<nil>   ← WINNER
(b) fixture marks every nested member disposable:                                    err=<nil>
neg  non-disposable root + non-disposable leaf:                                      err=check live prod.child: --bed-actions ... (D-DEP-3)
```

- **(a) propagate the parent's disposability in `bedActionsAuthorized`** — WINNER. A nested member's effective venue is its root's; the root's `disposable: true` authorizes, the leaf's own flag is a fallback. One rule in the guard's semantic home. Proven live by the `check-group` bed above.
- **(b) the bed fixture declares every nested member `disposable: true`** — it *works* for a leaf that repeats the flag, but it is per-fixture: every nested member of every disposable bed must repeat the flag, and a future nested member that forgets it re-breaks the same class. Rejected as the fix (the R3 workaround).
- **(c) the check runner threads the parent's disposability into the nested `--bed-actions` invocation** — rejected: the rule's semantic home is the guard; threading parent context through every caller duplicates the rule.
- **(d) fill the nested node's `Disposable` from the root in the shared classification tree** — rejected: it mutates a shared data structure to answer one authz question.

The winning candidate is (a); the diff implements it. No workaround ships.

## Change classification

**Breaking change + rollback:** the `--bed-actions` authorization gate now authorizes a nested in-substrate member when its ROOT deployment is `disposable: true` (previously refused with D-DEP-3). A caller that relied on the old refusal of such a nested member now sees it authorized — that is the fix; a top-level deploy's own flag, and a nested member of a NON-disposable root, are still governed exactly as before (the negative case stays refused). Rollback: revert this commit (restores the leaf-only check; the nested-member bed-actions refusal returns).
