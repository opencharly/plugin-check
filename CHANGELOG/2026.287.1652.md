# 2026.287.1652 — fix(diagnostics): exempt the sshd pre-transaction hook's container-systemd failure, conditionally (successor to #104)

## Summary

**Successor to `opencharly/plugin-check#104`**, which the validator auto-closed (Part II #7). Same change, same head content — **this PR exists so a corrected body gets a head that can be reviewed**, and it carries that PR's fix plus the citations it got wrong.

Every cold image build failed its `[image-build]` step on a benign pacman hook failure. The error tier already had a conditional entry for one post-transaction hook that calls systemd in a container
build (`pacman-post-transaction-hook-container-systemd`, anchored on the `Loading new kernel modules...` banner);
this adds its sibling for the openssh pre-transaction hook, which `opencharly/plugin-check#103` reproduces:

```
:: Running pre-transaction hooks...
(1/2) Marking sshd.service for restart...
System has not been booted with systemd as init system (PID 1). Can't operate.
Failed to connect to system scope bus via local transport: Host is down
error: command failed to execute correctly
```

pacman reports a hook that exits nonzero as that ONE generic wrapper error. Inside a container build systemd refuses because it is not PID 1, and marking a unit for restart is meaningless when there is no systemd to restart it — so the refusal IS the proof, as in the sibling entry.

**Conditional and line-bound, like its sibling.** The proof binds the claim to THIS hook, in order: the sshd
restart banner, systemd's container-init refusal it triggers, then the wrapper error within three intervening
lines. `ProofEndsOnLine: true` because the chain terminates in the line being claimed, so a SECOND wrapper error
in the same log (another hook failing alongside) is a different line and stays fatal; a wrapper error from any
other hook — device-manager, fontconfig, … — is still fatal, because the banner is not there.

**Why conditional and not a blanket exemption:** the offending line is literally
`error: command failed to execute correctly` with no package name, so an unconditional entry would also excuse a
genuine scriptlet failure of any package.

**Only COLD builds reach it, which is why it reads as intermittent and is not.** A warm run skips the
transaction (`cache=138/148`), so the line never appears and the step passes.
