# 2026.250.1816 — fix: emit the check-run candy source dirs on the CheckEnv wire snapshot

## Summary

`pluginSnapshotCheckEnv` now threads `RunnerConfig.CandyDirs` (already folded from the project's candy source scan — `candyDirsFromEnvelope`) onto the wire `CheckEnv` snapshot.

RCA: the host-side committed-APK anchor (charly `resolveCheckApk` → `checkhost.ResolveCommittedApk`) resolves an in-venue step's relative `apk:` path against the AUTHORING candy source tree from the check carrier's CandyDirs map. The plugin-side runner folded the map into its config, but the wire snapshot never carried it — so the baked-plan install steps of check-android-emulator-pod (`adb-install-apidemos` / `appium-install-apidemos`) reported "0 candies scanned". The wire field is added in the paired spec PR (opencharly/spec #121, `#CheckEnv.candy_dirs`); charly's carrier decodes it in the paired charly PR.
