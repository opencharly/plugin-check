# 2026.249.2119 — refactor(check): drop the group-kind IsGroup dependency (spec #105)

## Summary of changes

Plugin-check is the plugin-check consumer leg of the spec #105 group-kind removal (opencharly/spec v0.2026249.2106 deleted the `group:` #ResourceKind kind and the `spec.Deploy.IsGroup()` method). The post-migrate world has NO targetless member-bearing deploy: a former group bed is now a **primary substrate root carrying deploy-level member siblings**. This PR re-pins the contract and migrates every `IsGroup` site to position-derived logic (`len(d.Members) > 0` — deploy-level members ARE the former group shape), deleting the arms that guarded a shape that can no longer exist.

Concrete edits, accounting for every file in the diff:

- `candy/plugin-check/go.mod`, `go.sum` — spec **v0.2026249.1948 → v0.2026249.2106**, sdk **v0.2026249.1959 → v0.2026249.2114** (the sdk release that deletes deploykit's own group-root `IsGroup()` self-skip — without it this module cannot compile against spec 2106: the deleted method was called at sdk `deploykit/bed_session.go:71`; cross-repo RCA below).
- `bed_session.go` — the `ArbiterInvokeInput.IsGroup` population (`node.IsGroup()`) and the `CheckBedReply.IsGroup` derivation deleted (always-zero post-migrate: a bed claimant/root is always a substrate node); the libvirt user-session condition drops the `isGroup` disjunct (only the VM substrate needs the session daemon); stale "group bed" comment wording updated. The two wire FIELDS themselves remain spec-side residuals per the spec #105 merge note (consumed by plugin-preempt) — plugin-check simply never sets them non-zero again.
- `bed_run.go` — DEAD ARMS DELETED (the shape cannot exist): pre-run-cleanup `case d.IsGroup`, cleanup-target `case d.IsGroup` (members-down already runs as the default arm's `cleanup-members` phase), deploy-add `case d.IsGroup` (the root now deploys via the default arm — it has a substrate), failure-debug `case d.IsGroup` message (the substrate's own message applies). REAL BEHAVIOR RE-DERIVED from position: the member pre-build gate is now `len(d.Members) > 0` (the root's own substrate builds in Steps 1+2; members still pre-build because `bringUpMembersFresh` assumes pre-built images), and the Step-5 update gate is UNIFIED — the formerly exclusive group/root branches compose: member image rebuild (full gate) → members-down → the root's own `updateGateSteps` → members-up → check-live (an in-place root re-checks inside the member arm, where the substrate tail cannot).
- `live_gather.go` — the group live-dispatch arm (`entry.IsGroup()` → `pluginCheckLiveGroup`) and the whole dead `pluginCheckLiveGroup` function deleted; substrate dispatch (vm/local/pod) covers the migrated shape.
- `instrument.go` — `venueKindOf`'s dead `case d.IsGroup: return "group"` arm deleted.
- `instrument_test.go` — NEW `TestVenueKindOfIgnoresGroupField`: pins that the residual `IsGroup` field never drives venue classification and an all-zero descriptor is a pod. **This test FAILS on the pre-cutover tree** (the deleted arm returned `"group"`).
- `cmd_helpers.go`, `anchored.go`, `live_cmd.go`, `plugin_runner.go`, `bed_persist.go`, `live_gather.go` comments — stale group classifications updated to the post-cutover arm set.
