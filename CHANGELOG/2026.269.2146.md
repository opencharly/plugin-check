# 2026.269.2146 — fix(check): resolve a namespace-qualified deploy key by exact match first

## Summary

Apply charly#678's exact-key-first fix to plugin-check's relocated copy of
`resolveDeployNodeByPath`.

`resolveDeployNodeByPath` split the name unconditionally on `.`, so a
namespaced top-level deploy key (`charly.check-charly-vm`) was read as a root
named `charly` plus a member path, missed, and returned false. `checkVmTarget`
then failed to see the SSH venue, and a qualified VM bed's `check-live` fell
through to a CONTAINER lookup:

```
charly: error: command "check": container charly-charly.check-charly-vm is not running
```

while the running VM domain is the flattened `charly-charly-check-charly-vm`.

Fix: try the EXACT full key first; fall back to the member-path split only when
absent — mirroring spec.ResolveNodePath's exact-key-first contract (spec#164) and
charly#678 (`4ee24916`), which fixed the SAME bug at the core pre-connect layer.

Companion to opencharly/sdk#308 (which folds namespaced beds into the
resolved-project `Deploy` tree, so this lookup is even reached). Both are needed
for a qualified bed's `check live` from the umbrella root.
