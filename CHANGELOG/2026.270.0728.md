# 2026.270.0728 — feat(check): prereq-skip a bed whose pinned container engine is absent

## Summary

Add a **host container-engine prerequisite** to the check-bed setup: a bed that pins a concrete
`engine:` (the `kindcluster` R10 beds) is now a clean **prereq SKIP** (exit 3) when that engine's
CLI is absent on the host, instead of failing later at `deploy add`.

This closes the plan's **live-or-skip (R7a)** requirement for
`plan/kind-integration.md` §4 Phase 6: *"each bed gates on its engine being present
(`command -v docker|podman|nerdctl`); an absent engine is a **visible skip**, never a silent
pass."* The framework previously had only a GPU-specific bed prereq skip; this generalizes the
sibling case for the container engine, reusing the same `#CheckBedPrereqSkip` verdict (no schema
change).

The engine word **is** the CLI binary name (`#EngineName` = `podman|docker|nerdctl`, the 1:1
`KIND_EXPERIMENTAL_PROVIDER` mapping), so a `LookPath` miss is the gate. A bed declaring no
`engine:` declares no engine requirement and is never skipped. The GPU gate keeps its
long-standing `prereq-gpu-skipped` step name; the engine gate records `prereq-engine-skipped`
(both are members of the documented `prereq-*-skipped` family).

**Producer/consumer:** this is the producer half. The consumer is an `opencharly/charly` PR that
bumps the compiled-in `plugin-check` pin and adds the explicit `engine:` to the kindcluster bed
roots (so `bedEnginePrereqSkip` reads it) — landing after this merges.
