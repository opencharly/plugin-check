# 2026.243.0542 — fix(bed): the debug hint printed a command that cannot run

## Summary


### Root cause

The hint is keyed by the shared `kind: vm` ENTITY (`d.VMTemplate`). The live libvirt domain
and the managed ssh alias are keyed by the per-deploy DOMAIN IDENTITY — `charly-<BedDomain>`.

This is not a corner case. A bed always DERIVES from a shared template, so entity and deploy
differ for every VM bed, and the hint was therefore wrong every single time it printed.

The rest of this same file already had it right, which is what makes it a projection slip
rather than a misunderstanding:

  - bed_run.go:213,398 cleanup — `vm destroy <VMTemplate> --domain <BedDomain>`
  - bed_run.go:272 waitReady — its own comment: "the per-deploy DOMAIN IDENTITY
    (charly-<BedDomain> is the live domain + managed ssh alias, post-P33), NOT the shared
    kind:vm entity (d.VMTemplate)"
  - `charly vm destroy --help` — "--domain ... keyed by the DEPLOY not the entity"

Only the operator-facing message was left on the entity name.

## The fix

ssh targets `d.BedDomain`; destroy stays entity-scoped but carries `--domain <BedDomain>`,
matching the working cleanup path. The banner now names the real domain
(`charly-<BedDomain>`) instead of the entity, so what it reports is what `charly vm list`
shows.
