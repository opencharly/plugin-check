# 2026.288.1214 — fix(check): an empty plan resolution is a SKIP, not a pass — every arm, and the bed record

## Summary

`charly check run <bed>` runs one `check live` per nested child and banks each phase as a step. Every check mode had a path where the plan resolution comes back **EMPTY** — an image that baked no `plan:`, a deployment whose source declares none, a bed child whose own plan and `add_candies` contribute no steps — and on that path all four arms printed their no-plan sentence and `return nil`ed: **exit 0**. A phase that asserted NOTHING was therefore indistinguishable from one that asserted everything and passed, and in a bed it was recorded `ok: true` and counted in the summary.

Measured (`opencharly/distro-arch`'s `check-arch-vm`, run `2026.287.2125`): the phase `check-live-charly-cachyos-tailscale-test` PASSed in 4.057 s and its **entire log** was `No plan steps defined for this image.`, while its sibling `check-live-arch-host` ran nine real steps — the run's own step count could not say which of the two a reader had.

**This is the vacuous-PASS half of `opencharly/plugin-check#110`, which the issue states is a defect either way** — *"an empty resolution must not be reported as a pass"* — and it is the half that is independent of the candy and of `distro-arch#52`. It becomes a first-class **SKIP**, on both surfaces:

1. **The phase announces it.** All four arms (`check box`, `check live`, `check feature-box`, `check feature run`) now print `SKIPPED — <why>`, naming what resolved nothing and the issue, and return `CheckSkippedError`, which `mapCheckExitError` maps to **exit 3** — the convention's "nothing ran". The prose each arm already printed is preserved verbatim; the OUTCOME changes, not the message.
2. **The bed records it.** `charly check run <bed>` records such a step as SKIPPED — `stepResult.SkipReason` (new) — and `summary.yml` carries a per-step `skip_reason`, so `ok: true` beside `skipped: 0` can no longer read as "this phase asserted something and it passed". This is the same correction `stepResult.Skipped` made one layer down for charly#865 / `plugin-check#93` (*"the record said `ok: true` for a phase that asserted nothing"*), applied at the resolution boundary itself.

**It is deliberately NOT a failure.** A bed author may compose a child that legitimately declares no plan steps, and a skip is not a red — the same posture this struct already takes for a phase whose inner steps all skipped, and the posture the exit-code convention takes for a prerequisite skip. It is also not a pass, and that is the whole change.

**The decision the issue asked for, pinned here so the record cannot drift:** this issue's option **(a)** is the shape now in the tree — the child phase runs the child's composed plan with candy steps scoped by the venue they run in (`layer-direnv#7/#8` → `v2026.287.2155`, `layer-charly-check#43`, `layer-examplestep-deploy-consumer#7`), because the composition at `live_gather.go:375-419` is `child's own plan + host-deploy plan + candyAddSteps(add_candies)`. What remains, and what this cutover fixes, is that **an empty result of that composition is a skip, not a verdict**. Option (b) (filter candy steps out of a child phase) is NOT taken: the candy's steps are its own acceptance of the venue it ran on, and dropping them would hide that the child contributes nothing rather than say so.

**Premise movement, measured while preparing this PR:** the instance the issue cites no longer reproduces at `distro-arch` head `7ddfa87e` — the child `charly-cachyos-tailscale-test` now declares three `context: [runtime]` checks (`tt-tailscale-binary`, `tt-tailscaled-active`, `tt-tailscaled-enabled`), so its phase is no longer vacuous. That repair is exactly the bed-side fix a bed author should make; the plugin defect it exposed is what this PR closes, and the other beds whose children resolve nothing are now visible instead of green.

**Blast radius, named:** an operator-facing `charly check box <image>` / `charly check live <deployment>` on an artifact that bakes no plan changes from exit 0 to exit 3, and inside a bed the same phase stops being counted as a pass. Scripts that read exit 0 as "checked and passed" for such an artifact now see "nothing ran", which is the point.
